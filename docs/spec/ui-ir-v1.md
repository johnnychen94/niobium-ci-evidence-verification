# UI IR v1

- **Status:** Baseline
- **Decision:** [ADR-0008](../adr/0008-shared-software-renderer.md), [ADR-0009](../adr/0009-zon-screen-ir-and-tokens-codegen.md)
- **Implementation:** `libs/ui/core`

## Pipeline

`ViewModel → bind(ZON template) → UiTree → layout(tokens) → DisplayList + SemanticTree → rasterizer → backend`.

The same ViewModel, viewport, scale, theme, direction, and interaction state must produce byte-identical UiTree, DisplayList, and SemanticTree text snapshots (N1-AC-11).

## Templates

A screen template is a `.zon` file, `@import`ed with `TemplateNode` as the result type:

```zig
pub const welcome = ui_core.compile(ViewModel, @import("welcome.zon"));
```

Two layers of validation ensure that template errors surface at compile time:

1. ZON parsing itself rejects unknown fields, unknown node kinds, and values of the wrong type, such as pixel numbers or unknown tokens.
2. `compile` runs `template.check` at comptime; violating any of the rules below is a compile error. The error message includes the problem, the node kind, the id, and the field name.

`check` can also be called at runtime; that is how the rule tests are written. `bind` runs `check` once more before binding.

All fields of `TemplateNode` other than `kind` are optional, so whether a field is allowed can be decided per node kind.

### Nodes (closed set)

| Node | Required fields | Optional fields | Semantic role |
|---|---|---|---|
| `window` | `title`, `children` | — | window |
| `stack` | — | `axis`, `gap`, `padding`, `alignment`, `width`, `height`, `children` | None (children attach to the parent) |
| `card` | — | `gap`, `padding`, `alignment`, `width`, `height`, `children` | group |
| `text` | `text` | `style`, `tone`, `width` | text |
| `image` | `source` | `label` (alt text), `width`, `height` | image |
| `button` | `id`, `label`, `action` | `variant`, `enabled_bind`, `width` | button |
| `checkbox` | `id`, `label`, `bind` (bool) | `enabled_bind` | checkbox |
| `radio_group` | `id`, `label`, `bind` (enum), `options` (≥ 2) | `enabled_bind`, `gap` | radiogroup, with each option as radio |
| `link` | `id`, `label`, `action` | — | link |
| `progress_bar` | `bind` (f32, 0–1), `label` | `width` | progressbar |
| `progress_ring` | `label` | — | progressbar (busy) |
| `scroll` | `id`, exactly one child | `max_height`, `width`, `height` | scrollarea |
| `modal` | `title`, `children` | — | dialog |
| `divider` | — | — | separator |
| `spacer` | — | `width`, `height` | None |
| `folder_picker` | `id`, `label`, `bind` (string), `fallback` | `enabled_bind`, `width` | button; text when falling back |

Every node except `window` may carry `visible_bind` (bool). When the value is false, the whole subtree is left out of the UiTree.

Other structural rules:

- The root node must be `window`, and `window` cannot be nested.
- `modal` may only be the last child of `window`, so that it is always drawn on top.
- `radio_option` must not appear in a template; it is generated by `bind` from `options`.
- An id may consist only of lowercase letters, digits, and `_`, has length 1–64, and is unique within a template.
- A template has at most 512 nodes and a nesting depth of at most 24 levels.

The `title` of `window` and `modal` is used only as the semantic name and as the native title bar text; the visible title is provided by a child `text` node.

### Value domains

| Field | Values |
|---|---|
| `axis` | `row`, `column` |
| `alignment` | `start`, `center`, `end`, `stretch` (cross axis) |
| `style` | `title`, `heading`, `body`, `caption`, `mono` |
| `tone` | `normal`, `muted`, `accent`, `danger`, `success`, `warning` |
| `variant` | `primary`, `secondary` |
| `source` | `logo`, `icon` |
| `fallback` | `text` |
| `gap`, `padding`, `max_height` | token: `none`, `xs`, `sm`, `md`, `lg`, `xl`, `xxl` (`space`), `logo`, `list`, `field`, `modal` (`size`) |
| `width`, `height` | `.content`, `.fill`, `.{ .fixed = <token> }` |

Templates contain no pixel coordinates, colors, or font names, and no other style fields. Visual values come only from `libs/ui/tokens/tokens.json`.

### Defaults

| Node | Default |
|---|---|
| `window` | `width = fill`, `height = fill` |
| `stack` | `axis = column`, `gap = md`, `width = fill` |
| `card` | `gap = md`, `padding = lg`, `width = fill` |
| `modal` | `gap = md`, `padding = xl` |
| `radio_group` | `gap = sm` |
| `scroll`, `progress_bar`, `divider`, `folder_picker` | `width = fill` |
| `button` | `variant = secondary` |
| Others | `width = content`, `height = content`, `alignment = start`, `style = body`, `tone = normal` |

## Bindings and actions

- `bind`, `enabled_bind`, and `visible_bind` reference ViewModel field names. check verifies that the field exists and that its type matches its use:
  - `[]const u8`: text placeholders and `folder_picker`;
  - `bool`: `checkbox`, `enabled_bind`, `visible_bind`;
  - `f32`: `progress_bar`;
  - enum: `radio_group`, and every option's `value` must be a member of that enum.
- Text fields (`text`, `label`, `title`, an option's `label`) may contain `{field}` placeholders, and the field must be `[]const u8`. Any other `{` or `}` is an error; escaping is not supported.
- `action` is a closed enum: `next`, `back`, `install`, `cancel`, `close`, `launch`, `retry`, `show_license`, `choose_folder`.

## Capabilities and fallback

A backend declares its native capabilities through `Capabilities`; currently the only one is `native_folder_picker`.

A node that needs a capability must declare `fallback`; omitting it is a compile error. If the backend does not support that capability at bind time:

- the node is marked `fallback_active`;
- the bind result's `diagnostics` gains an entry `{id, capability, resolution}`;
- the node is presented in its fallback form: `folder_picker` falls back to read-only text, is not focusable, and has semantic role text.

## Layout

- The unit is integer device pixels. A token is converted once when used: `px = floor(logical × scale / 100 + 0.5)`, with scale 100, 150, or 200.
- Containers lay out their children as a stack; containers are `window` (a column with no padding or gap), `stack`, `card`, `radio_group`, and `modal`.
- `content` takes the natural size, but no more than the available space; text wraps to the available width. `fixed` takes the token value. `fill` splits the remaining space evenly, with the remainder going to the last fill child.
- With `alignment = stretch`, non-fixed children fill the cross axis.
- `modal` does not take part in the window's layout; it overlays the window, centered: width is `min(size.modal, viewport − 2·xl)`, and height is the content height, no more than `viewport − 2·xl`.
- The viewport height of `scroll` is capped by `max_height`. The child width is the scroll width minus the scrollbar gutter at the trailing end (`md`), which is reserved whether or not the content overflows; in RTL the gutter is on the left. When the content overflows, the offset comes from the interaction state and is clamped to `[0, content height − viewport height]`; the visible region of descendants is clipped to the viewport.
- The natural size of leaf nodes is given by the kit's `measure(env, node, max_width)`. Text width is provided by `TextMeasurer`, which ui_render implements with an embedded font.
- Line-break opportunities are after spaces, before and after CJK characters, and at `\n`; a single word wider than the line is broken between code points.
- RTL: after all layout is complete, every rectangle is mirrored left-to-right within the window. Text itself is not reordered.

## DisplayList

Commands (coordinates in device pixels):

| Command | Description |
|---|---|
| `fill` | Fills a rectangle, optionally with rounded corners |
| `stroke` | Strokes a rectangle, optionally with rounded corners |
| `text` | One line of text: top-left of the line box, line height, font (style and pixel size), color, optional underline |
| `image` | Product logo or icon |
| `icon` | Built-in icon: `check`, `chevron`, `folder`, `warning`, `failure`, `success` |
| `ring` | Indeterminate progress ring; `phase` is in thousandths of a turn |
| `clip` / `unclip` | Appear in pairs, wrapping the descendants of a scroll |

The DisplayList is generated in UiTree preorder. The kit's `emit(env, node, placement, state, list)` draws each node before its children:

- `placement` contains the rect and the visible-region clip, and for scroll also the offset and range;
- `state` contains hovered, pressed, and focused.

The kit may also declare an `overlay` with the same signature, which draws after the subtree ends; it is used for scrollbars.

## SemanticTree

The SemanticTree records role, id, name, value, bounds, focusable, state, and actions for every node that has a role:

- name is taken from the node's text.
- value: `N%` for progress_bar, the path for folder_picker.
- state: `disabled`, `checked`, `selected`, `focused`, `busy`.
- actions: `press`, `toggle`, `select`, `scroll`.

`stack` and `spacer` have no role; their children attach under the nearest ancestor that has a role.

## Focus and input

Interaction state (`Interaction`) is keyed by node id and remains valid after rebinding; `reconcile` clears the state of nodes that have disappeared or been disabled.

- **Scope:** when a modal is present, only the modal subtree receives pointer, focus, and key input.
- **Focus order:** preorder traversal within the scope; focusable nodes are enabled button, link, checkbox, and radio_group, plus non-fallback folder_picker. Tab and Shift+Tab move focus cyclically, and the focus ring is shown after keyboard navigation. If focus lands inside a scroll, that scroll's offset is adjusted so the node is fully visible.
- **Pointer:** activation requires press and release on the same control; pressing gives focus but does not show the focus ring. The scroll wheel acts on the innermost scroll under the pointer.

Key behavior:

| Key | Behavior |
|---|---|
| Enter | Activates the focused button, link, or folder_picker; otherwise activates the first enabled primary button in the scope |
| Space | Activates the focused button, link, folder_picker, or checkbox |
| Arrow keys | Move the selection within the focused radio_group, without wrapping; left and right are swapped in RTL |
| Escape | Means "leave": inside a modal, looks in order for an enabled button whose action is `close`, `back`, `cancel`; on a page, looks in order for `cancel`, `close`. Activates the first one found |

The result of activation is an `Intent`, which the screen controller turns into an engine intent or a ViewModel update:

- `action`: button and link;
- `toggle`: the checkbox's id;
- `select`: the radio_group's id and the option index;
- `choose_folder`: the folder_picker's id.

## Snapshot format

All three snapshots have one node or command per line, with two spaces per indentation level; strings are escaped as Zig string literals:

```text
UiTree:      button #install primary action=install w=content h=content "Install"
DisplayList: fill 535,408 81x28 r6 #0B63CEFF
Semantic:    button #install "Install" 535,408 81x28 focusable +press
```

A format change is equivalent to a golden change; the affected snapshots must be updated in the same commit.

## Verification

The tests in `libs/ui/core` cover the following:

- Templates: parsing, unknown fields and nodes, missing ids, invalid ids, duplicate ids, inapplicable fields, missing required fields, nonexistent or mistyped bindings, placeholder errors, unknown options, structural rules;
- capability fallback and diagnostics;
- determinism of the three snapshots, and the effect of scale and RTL on geometry;
- focus order, pointer and keyboard activation, modal scope, scroll clamping, reconcile.

Offscreen pixel goldens are covered by `ui_render` and `tests/golden` (N1-AC-12).
