# Product manifest v1

- **Status:** Baseline
- **Decision:** [ADR-0003](../adr/0003-strict-json-manifest.md)

The product manifest describes the desired state of one release. It is a target authorized by a TUF channel role (see [tuf-profile-v1](tuf-profile-v1.md)) and is generated by `nbpack product compose`.

## Example

```json
{
  "schema": 1,
  "min_installer": "0.1.0",
  "product": {
    "id": "com.example.hello",
    "name": "Hello",
    "publisher": "Example Inc.",
    "version": "1.2.0",
    "release_sequence": 3
  },
  "install": { "default_scope": "user", "allowed_scopes": ["user", "machine"] },
  "components": [
    {
      "id": "runtime",
      "title": "Hello Runtime",
      "required": true,
      "default": true,
      "artifacts": { "macos-aarch64": "sha256:<64 hex>", "linux-x86_64": "sha256:<64 hex>" }
    }
  ],
  "integrations": {
    "shortcuts": [{ "name": "Hello", "entrypoint": "runtime.main" }],
    "file_associations": [{ "extension": ".hello", "entrypoint": "runtime.main", "description": "Hello Document" }],
    "services": [{ "id": "hello-agent", "entrypoint": "runtime.agent", "start": "manual" }]
  },
  "bootstrap": { "entrypoint": "runtime.main", "protocol": 1 },
  "experience": { "accent": "#3B5BDB", "license_text": "…", "welcome_text": "…" }
}
```

## Field rules

- Only `schema`, `min_installer`, `product`, `install`, `components`, `integrations`, `bootstrap`, and `experience` are allowed at the top level; unknown fields at any level are rejected.
- Forbidden fields: `pre_install`, `post_install`, `script`, `exec`, `shell`, `command`; appearing at any level returns `error.ForbiddenField`.
- `schema` must be `1`; a larger value returns `error.UnsupportedSchema` (fail closed). A `min_installer` higher than the current installer version returns `error.InstallerTooOld`.
- `product.id`: reverse domain name, `[a-z0-9.-]`, 3–128 bytes; it determines the install root directory name.
- `product.release_sequence`: positive integer, monotonically increasing; `product.version`: semver text, may be downgraded.
- `install.default_scope` must be one of `allowed_scopes`.
- `components[].id`: `[a-z0-9_-]`, 1–64 bytes, unique; `__installer_runtime` is reserved. At least one component must be `required: true`.
- `components[].artifacts`: keys are `<os>-<arch>` (`macos-aarch64`, `macos-x86_64`, `windows-x86_64`, `windows-aarch64`, `linux-x86_64`, `linux-aarch64`), values are `sha256:` + 64 lowercase hex digits.
- An `entrypoint` reference has the form `<component>.<entrypoint-name>` and must point to an entrypoint declared in the component metadata.
- `services[].start`: `auto` or `manual`. A service can be registered as a system service only in `machine` scope; in `user` scope it is registered as a user-level agent (launchd LaunchAgent / systemd --user / Windows user-level startup is not supported and returns `error.CapabilityUnsupported`).
- `experience`: only `accent` (`#RRGGBB`), `license_text`, `welcome_text`, and `icon_png` (base64 PNG, ≤ 256 KiB) are allowed; an accent with insufficient contrast is adjusted at runtime, and the manifest is not rejected.
- Size limits are in `contracts.Limits`: manifest ≤ 1 MiB, JSON depth ≤ 32, components ≤ 64, ≤ 32 per integration kind.
